1) Зачем скрывать поля класса?
Чтобы объект нельзя было «сломать» снаружи. Если поле открытое (public), в него можно записать любое значение, например отрицательный баланс, и объект окажется в неправильном состоянии, а ошибка проявится позже в другом месте программы. Когда поле закрыто (private), менять его можно только через методы и свойства класса, а они проверяют значения. Так класс сам защищает свои данные

2) Чем свойство отличается от поля?
Поле — это переменная внутри класса, которая хранит данные. Свойство — это механизм доступа к полю: через get данные читают, через set записывают, и в них можно добавить проверку. Снаружи свойство выглядит как обычное поле, но класс контролирует, что в него записывают. Обычно поля делают private, а свойства public

3) Что произойдёт, если не объявить ни одного конструктора?
Компилятор сам добавит конструктор по умолчанию — без параметров и пустой. Объект можно будет создать через new, а его поля получат значения по умолчанию: 0 для чисел, null для строк и объектов, false для bool

4) Как конструктор связан с инкапсуляцией?
Конструктор вызывается при создании объекта и задаёт начальные значения скрытых полей, проверяя их. Поэтому объект с самого начала находится в правильном состоянии, и нельзя создать «пустой» или некорректный объект в обход правил класса. Вместе скрытые поля, свойства и конструктор делают класс надёжным: конструктор контролирует создание, а свойства и методы — изменение данных

5) Можно ли изменить свойство только для чтения после создания объекта?
Нет. У свойства только для чтения нет set (например, { get; }), поэтому его значение задаётся один раз — в конструкторе. После создания объекта изменить его уже нельзя, это защищает данные от изменений
